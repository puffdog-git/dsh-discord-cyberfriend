# 語音可靠性與模型增量播放

2026-11-13。本次先改善插話誤判、斷線時的舊音訊及串流提前結束判斷，再增加選用的模型增量語音。維持外部 TTS 與 STT 獨立，不改為內建推理引擎。

## 插話

原先第一個超過音量門檻的 PCM 封包便可中止 AI，短促聲響也可能觸發。現在持續發聲預設 400 ms，允許短停頓，但近期音訊至少 65% 為有聲，零星聲響不能一直累積成插話。這是能量檢測，不是聲紋或聲學回音消除。

「使用者說話時中止 AI 語音」仍是總開關，既有關閉設定不會自動打開。確認方式：

- **辨識出文字後中止**：預設。STT 成功且文字有效後，才取消說話當時捕獲的播放及模型工作。取消依工作 ID，不會用過時辨識結果誤停新工作。
- **持續發聲後中止**：較快。達到發聲門檻即中止；外放回音仍可能觸發，建議耳機環境使用。

「略過疑似播放回音」預設開啟，只比較當時確實正在播放的人聲與辨識文字；高度相似時不觸發新回覆。刻意覆誦 AI 時也可能被略過，可關閉。沒有消除原音訊回音，亦不識別背景音樂的歌詞回音。STT 仍會接收音訊，已提交用量照常計算。

設定門檻後重新加入房間生效。語音控制台顯示最近插話／疑似回音的判斷原因，僅保留有限 ID、時間與原因，不保存錄音。

## 斷線與截斷

- 斷線立即取消正在合成、等待模型句段、正在播放及待播工作，並停止該次接收／辨識。恢復後不自行重播舊回答或舊音樂。
- 短暫斷線保留既有有限次數恢復；4014 等待 SDK 握手，不盲目 rejoin。恢復後重新建立接收器，不延用半句音訊。
- 移出原房間、伺服器靜音／限制發話、連線銷毀或恢復逾時停止，需要確認權限及目的地後重新加入。
- 手動離開會取消恢復；舊 Gateway 清理不覆蓋新的回呼，晚到 Ready 不使已停止連線復活。
- 播放器 Idle 不再一律表示整句完成：原始串流還沒結束便停播會標示失敗、取消上游，不自動重送已播過的內容。這能避免「前半句播完卻被記為成功」，不保證網路不會斷流。

加密、DAVE 與真正網路握手仍由 @discordjs/voice 負責；本次未另寫加密實作。

## 模型邊回覆邊說話

在「語音與音樂」啟用「模型邊回覆邊說話（選用）」。預設關閉，不自動啟用收聽或加入房間。

適用 Bot 的真人語音輸入、綁定文字頻道、自動朗讀、原文配音及支援 PCM 串流的外部 TTS。DSH 原生 Agent 讀取本機已確認的 agent/assistant-stream 事件；獨立 DSH Provider 模式讀取 text-delta。思考內容不送往語音。自訂非串流 API 沿用完整回覆。

目前原生 Agent **只有當次工具白名單為空**才提前朗讀；允許搜尋、音樂、唱歌或其他工具時維持完整回答。插件不會為加速而自動移除工具權限。這是比「模型實際沒有用工具」更保守的條件。

完整句段先做文字處理及敏感資料遮蔽，再送外部 TTS。句段透過同一個 FFmpeg／播放器依序輸出，可在模型尚未產生後文時開始說話。每句可能各自呼叫 TTS、計費及採樣，並非所有 Provider 共用一次雙向合成連線。

日文翻譯、待審稿、一般錄音語音泡泡、圖片回覆、閒聊判斷與不支援串流的接口不走這條增量路線。增量使用既定 TTS 語氣，不等待整段模型情緒 metadata。控制標記、程式碼、連結、模型重試或輸出改寫會阻止／停止增量；若已開始，最終文字送出時不再重讀整段。

文字段數、字數、TTS 字數預算、總音訊時長、設定／權限核對及取消皆有界。斷線、插話或停止會喚醒等待下一句的管線並結束，不留下等待中的 FFmpeg。已聽到的內容不能撤回，因此此功能預設關閉；最終文字送出失敗時停止剩餘語音並保留不確定性。

## 延遲資訊

成功的增量工作顯示模型首句、首段語音準備及「收句後至首音」時間。收句後從接收器交出一整句 PCM 起算，涵蓋轉檔、STT、模型與首段 TTS，但不包含使用者說話時間及收句前靜音等待。這些是本機管線指標，不等於遠端實際聽到的時間。

## 驗證界線

測試包括真 Opus 解碼、真 FFmpeg、實際 responder／模型讀取器／DSH 會話橋接，以及短雜音、稀疏聲響、持續發聲、疑似回音、辨識晚到、合成中斷線、等待後文時斷線、4014、靜音、銷毀、舊回呼與提前 Idle。模型、STT、網路狀態與最終 Discord 播放使用替身；沒有真人回音消除品質、真網路故障矩陣或付費雲端延遲保證。
