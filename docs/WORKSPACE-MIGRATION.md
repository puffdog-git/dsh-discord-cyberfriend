# 同帳號工作區與保留歷史的會話搬移

在「DSH 會話與外部人格」選擇工作區分組方式：

- **依登入帳號共用**：同一個 Discord 登入帳號的私訊、群聊與伺服器頻道使用同一個工作區。Bot 與使用者帳號各自一個；每個頻道仍是獨立 session，不混合聊天逐字稿。
- **依對話對象分組**：保留舊版管理者私訊／其他私訊／伺服器分組規則。既有安裝的預設不會悄悄改變。

工作區是外部人格／記憶插件可以使用的共同定位，不保證每一套記憶插件都自動共用記憶：仍取決於該插件按工作區、人格或 session 綁庫的設定。群聊工具授權、管理者判定及私人資料存取規則不變；記憶插件本身也應保有公開／私人範圍控制。

## 搬到新工作區

在「Discord 對應會話」填寫完整路徑，按「保留歷史並移到此工作區」。目錄不存在會建立；也可以按「保留歷史並使用帳號共用工作區」，取消該會話的手動路徑例外。

DSH 的 session 標頭工作區路徑不可直接改寫。因此插件使用宿主的 seed API 建立新 session，逐筆核對完整歷史，再保存新的 Discord 綁定。這是一次搬移建立一次新 ID，不是每次聊天重開 session。原 session 及其檔案保留；不刪除來源。

執行中、排隊中、未完成的回合、不完整歷史、候選歷史不一致或搬移期間來源有變化，均拒絕切換。綁定保存失敗會保留原綁定。中途失敗可能留下未綁定的候選 session，錯誤會提供 ID 供核對，不能把它當作搬移成功。

「綁定既有會話」是改接另一個既有 session，**不合併兩段歷史**；「開始新會話」則是重新開始，與搬移不同。

## 不會自動搬動的資料

- 舊工作區內的一般檔案、人格設定檔、外部記憶庫／圖譜、外部插件按 session 綁定的設定，仍需依其插件移轉方式處理。
- 舊記憶來源與維護回執保留原定位，不偽造為新工作區資料；搬移後新增的記憶來源會使用新定位。既有來源去重規則不變。
- 舊 session 的排程與延後工作不能直接冒用新 session；原綁定核對會阻止過期工作送到錯誤位置。
