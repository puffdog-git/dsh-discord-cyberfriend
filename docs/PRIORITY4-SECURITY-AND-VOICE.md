# 前四項安全與語音修復（2026-11-13）

本文件取代同日生態系審核中「前四項尚未修復」的狀態。

1. 管理 API 使用宿主真正的連線驗證，核對來源並要求寫入使用 JSON。未登入、偽造登入、跨站請求，以及不符格式的寫入會被拒絕；不因為來源是 localhost 就放行。
2. Discord 自有設定檔的憑證以 Windows DPAPI CurrentUser 保護；舊明文設定在啟動時遷移，保存失敗不覆蓋原檔。日誌、錯誤與 API 回傳移除已知金鑰，既有日誌亦經清理。這不代表其他插件的憑證或全部聊天資料都已加密；任意歷史未知秘密不保證可辨識。搬到另一台電腦時須重新設定憑證。
3. 翻唱與下載插件維持獨立。下載工具預設使用 public-only 網路政策：逐次解析 DNS、核對所有地址並固定實際連線地址，HTTP 重新導向與 HTTPS CONNECT 同樣檢查。禁用外部下載器、插件與 JS 執行器，FFmpeg 後處理限制為本機檔案／管道。無法安全執行時拒絕，不改用未受保護的下載路徑；部分需要 JS 的網站因此可能無法下載。這不是作業系統層級沙箱。
4. Discord 可明確選擇本 TTS 的 dshTts 或宿主 speechSynthesis；指定服務失敗不換另一套，避免聲音錯用與重複計費。錄音訊息回覆沿用中日配音流程：日文原生語音與中文文字分開交付，既有日文不重翻，取消不外送。仍須選用支援日文的音色。

## 驗證

- Discord 236 項 Node 測試、97 項前端行為檢查通過。
- 翻唱橋接 8 項、網路限制 5 項通過；真實 yt-dlp 與 FFmpeg 使用本機測試音訊，驗證資訊取得、下載、轉檔與私網重新導向拒絕。
- 外部 MiMo 實際服務程式＋HTTP 替身，與 dshTts 同時存在時驗證指定宿主服務；錄音日文走真正語音交付及 FFmpeg，但最終 Discord 請求攔截。
- 宿主驗證確認設定已加密、憑證不變、未登入 401／跨站 403／非 JSON 寫入 415；保留 memU 與原有開關。
- 沒有付費 API 合成、真歌曲下載或對 Discord 發測試訊息。

## 介面與文字

設定分區改為橫排模塊，自動依面板寬度換行。修正控制項擠壓中文、來源卡片說明溢出，以及空白搜尋／清空表單可點卻沒有動作的情況。

Discord、TTS 與語音交付介面右上角可切換「繁體中文／简体中文」，共用瀏覽器偏好，重新開啟仍保留，切換時不清除尚未儲存的設定。使用內附 OpenCC 字典，不呼叫模型。

四種對象設定中的「AI 回覆字體」獨立選擇保留模型輸出、繁體中文或簡體中文。本機轉換保護程式碼、網址、郵件、Discord 標記與含假名日文；不改日文配音及媒體控制標記。預設保留模型輸出。這不是修改其他插件或整個 DSH 的回覆語言。

Token 統計的兩部分都屬於本插件：服務回報部分與未取得回報時的暫估部分。今日／本月合計包含兩者，不是呼叫次數、整個帳號用量或金額；失敗／中斷也可能暫估。

UI 模擬檢查涵蓋 96 組分區／寬度組合、163 個可操作按鈕點擊、服務失敗提示與繁簡往返。依賴連線、非空資料或實際服務的其他按鈕仍需滿足其前提；不宣稱每一家雲端服務與真平台都完成實測。
