# 使用者帳號語音與Bot功能對齊（2026-11-13）

使用者帳號新增固定discord.py-self 2.1.0接收介面卡：經同一登入的voice websocket取得允許使用者的SSRC，UDP RTP驗證／AEAD解密／DAVE解密，再把Opus交給原有Node接收器、能量門檻、PCM與STT流程。不是開啟桌面麥克風，不保存收到的錄音檔。

收聽仍預設關閉。需「語音與音樂」啟用語音、允許房間、綁定同伺服器文字頻道、收聽開關、同意及允許使用者名單；需STT模型就緒。使用者帳號還需關閉僅觀察模式，AI自動回覆也必須開啟才會回答。沒有自動改動既有設定。

同一房間、共用回覆歸屬時只由一個介面送STT；優先主介面，否則原已加入的介面。分開人格模式才允許各自辨識與回答。兩個帳號分開取消辨識與播放，離開其中一邊不取消另一邊的STT。

收到的封包需吻合account、房間、guild、nonce；未知／不允許SSRC不解密。重複／倒序封包略過，待處理封包有上限，同時最多兩位解碼，沿既有單句／每日STT預算與800ms收句。移房、斷線、換帳號、撤回同意不提交舊音訊或晚到逐字稿。收聽支援目前選定的AEAD XChaCha20 RTP-size模式；其他模式拒絕，不降級繞過DAVE。

PCM輸出以序號及有限queue傳給Python AudioSource，來源明確結束並排空才成功；早停、斷線或逾時不重播。背景混音沿既有VoiceMixer。增量朗讀仍預設關閉，只適用原文配音、可串流TTS與當次無工具的真人語音路線；翻譯／審稿保留完整回覆。

## Krisp與音質

兩種帳號都直接發送音訊，不經Discord桌面程式的麥克風DSP，因此未套用Krisp、麥克風降噪、回音消除或自動增益。介面會顯示這項資訊，沒有無作用的「關閉Krisp」帳號開關，也不更改桌面Discord的設定。

FFmpeg使用audio用途編碼；Python PCM使用audio/music用途編碼。仍有Opus有損壓縮、來源音質、音量設定與可選的BGM降音量，不能稱完全無音質損失。[Discord的Krisp說明](https://support.discord.com/hc/en-us/articles/360040843952-Krisp-FAQ)描述的是其用戶端降噪選項。

## 驗證與限制

全部採隔離替身Discord、模型、STT與TTS。使用真Opus編解碼、真PyNaCl驗證含RTP extension封包、真本機FFmpeg與PCM混音；DAVE呼叫參數與失敗不降級採替身驗證，不代表真實伺服器金鑰協商／輪替已驗收。真正index處理鏈驗證user逐字稿→模型→TTS→PCM→單次播放回執。

此接收器依固定版本的較低層socket／websocket hook實作，升級discord.py-self要回歸。沒有加入真語音房、真人錄音、外送或付費呼叫。封包倒序採略過，尚無完整jitter buffer／丟包修復；遠端聽感、長連線與真DAVE仍留給目前代理後續帳號驗收。
