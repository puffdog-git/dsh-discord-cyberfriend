# Discord 串流、語音互動與對話總覽

2026-11-13。這一版延續 Discord 產生文字與語氣 → 外部 TTS 回傳音訊 → Discord 播放的分工。TTS 不需要 Discord 帳號或通訊專用端點。

## 串流與連線恢復

「低延遲串流」只在 Bot 與可宣告 PCM 串流的 TTS 接口上使用，支援直接 dshTts、宿主相容服務與新版 dsh-tts HTTP。其他接口、個人帳號保留完整音檔播放。雲端支援原生串流時逐塊傳輸；不支援或需套用速度／音量時按句合成並逐段播放。日文翻譯先對完整正文處理一次，避免逐段翻譯破壞上下文。

PCM 以背壓串接 FFmpeg 及 Discord Opus 編碼，不產生完整語音暫存檔。控制台顯示原生／分段模式及首音訊延遲；這是本機開始傳輸的時間，不能代表遠端成員已聽到。中途失敗沒有完整成功標記，不自動重新合成或重播整句。

語音 SDK 負責 DAVE 與加密握手。短暫斷線最多等候三輪，每輪五秒；一般斷線在後續輪次嘗試 rejoin，4014 先等 SDK 握手，不無限重試。被移動或踢離原房間會停止，須重新確認目的地。舊連線清理不會移除新連線的 Gateway 回呼。文字 Gateway 與語音恢復分開顯示。

## 人格音色、記憶庫與成本

語音控制台的「人格音色、記憶庫與成本概覽」唯讀列出 Discord 綁定的 DSH 會話／工作區、實際聲音方案與語言；完整方案與人格優先順序仍在 TTS 設定頁管理。最多顯示四十個綁定，不合成試聽、不變更聲音。

「唯讀檢查記憶庫綁定」使用已安裝 memU 的 diagnoseSession。未綁定、關閉、缺少 libraryId 或服務不可用會分別提示，不建立記憶庫、不推定同一工作區共用記憶。未安裝 memU 時顯示無法查詢。

統計包含 LLM Token、TTS 提交字數、播放毫秒、STT 提交秒數及會話分項。翻譯另列最近最多六十筆模型呼叫中的 Token；不是完整日／月翻譯帳單。使用者可填 LLM 每百萬 Token、TTS 每百萬字元、STT 每分鐘單價及幣別；零代表未估算。模型價差、快取、重試、服務商計費口徑及原生 DSH 未提供的用量可能造成差異，以帳單為準。每個日期最多保留二百個會話統計項目，其餘併入未分類。

## 選用語音輸入

預設不收聽、不自動回覆；個人帳號仍只輸出。若要使用：

1. 在 DSH 語音輸入設定啟用並準備所選 STT 模型／服務。本插件不自動下載模型或切換服務。
2. 告知參與者音訊用途、所選本機或雲端 STT 及是否交給 AI，取得同意。
3. 設定允許的語音房、收聽使用者 ID，開啟「啟用 Bot 語音收聽」與同意欄位，儲存後重新加入 Bot 房間，並綁定同伺服器文字頻道。空白名單不收聽。
4. 需要 AI 回覆時才開啟「將逐字稿交給 AI 回覆」；需要 AI 語音回答時另開朗讀綁定頻道。沿用既有權限、冷卻、人格、預算與審稿流程。
5. 「本機語音字幕」可查看辨識結果。關閉收聽或離開房間會取消工作；停止辨識只取消目前工作，不改永久設定。

接收依 Discord 使用者分軌，不把多人混在同一份辨識；同時最多兩人，每人一個工作。800ms 靜音收句，RMS 門檻與至少 200ms 有聲資料過濾短雜音，預設每句最多十五秒、每日提交六百秒，可調整。這是基本能量 VAD，不是聲紋辨識，也沒有消除遠端麥克風回音。音訊只在有界記憶體保存，再轉成 16kHz 單聲道 WAV 送指定 STT；雲端 STT 仍會接收音訊。辨識有四十五秒期限，已提交但失敗也計入秒數，取消或權限變更後的遲到結果丟棄。

可選「使用者插話時停止 AI 發話」；只對允許的發話者生效，停止目前 AI 語音、尚未播放的自動語音及該使用者尚在生成的回覆，不停止背景音樂。已送出的文字不撤回。

## 本機字幕與音樂

字幕預設關閉；開啟後顯示中文正文、實際日文配音及播放狀態，不額外向 Discord 發送字幕訊息。輸出最多二十筆、輸入最多十筆，五分鐘有效，只保留於記憶體；沒有逐字或中日語義時間對齊。

音樂預設「暫停後接續」。Bot 可改選「雙音軌壓低／漸變」：背景音樂與人聲同時輸出，人聲期間音樂漸降至指定比例，結束後恢復，約 140ms 漸變，人聲有短淡入。每次只有音樂、人聲各一軌；有界緩衝與背壓避免長音樂全解碼進記憶體。設定對下一首音樂生效，個人帳號維持暫停後接續。停止、斷線及離開會清理兩軌，不自動重播。

## 影片與貼圖

「影片抽幀辨識」預設關閉。啟用後對既有允許來源的 MP4／WebM 抽取最多六張 JPEG，限制 12MiB、兩分鐘、1600萬像素，沒有音軌轉錄或完整逐幀理解。既有圖片／GIF 選路沿用；超限會拒絕，不無限下載。

個人帳號的貼圖名稱搜尋原本已具備伺服器與官方貼圖包的名稱／標籤搜尋、快取與逾時。本輪確認及回歸，沒有重複加一套搜尋。

## 驗證界線

自動測試採模擬 Discord 傳入、發送與 STT 服務，實際執行 FFmpeg、Opus 編解碼、混音、影片抽幀與瀏覽器 UI。另以免費 Edge 實際合成，跑完中立 HTTP → PCM → FFmpeg → Opus 編碼；沒有加入真實房間、發訊息、收聽成員或使用付費雲端額度。真實 Discord 網路／DAVE 握手、真人麥克風與付費 Provider 延遲仍需指定環境驗收，不能由模擬結果保證。

### 本機 SenseVoice 實測（2026-11-13）

此開發電腦已透過 DSH 正式管理 API 啟用內建 `@deepseek-ai/dsh-experimental-voice-input-bundle`，下載並校驗 SenseVoiceSmall INT8／Silero VAD 模型，使用 `sensevoice-local`。辨識在 CPU 執行，不需要佔用 TTS 的顯示卡，也不需要雲端金鑰。模型與執行程序由宿主管理，閒置五分鐘卸載，下一次辨識可重新喚醒。此為本機安裝設定，不會讓開源插件在別人的電腦自動下載模型。

驗收使用免費 Edge 製作的中文測試音訊，先轉為 48kHz 雙聲道，再經真正 Opus 編碼、接收器的逐人解碼／VAD、FFmpeg 16kHz 單聲道轉換、實際 DSH `speech/transcribe` 與 SenseVoice 推理，最後進入 VoiceInput 的隔離回覆接收端。8.44 秒音訊單次推理約 0.14 秒，完整保留「明天下午三點，到圖書館整理筆記」的句尾；「辨識」有一處同音誤字，結果為簡體字。這不是辨識準確率或延遲保證，也不是繁中輸出品質驗收。

允許名單外的說話者未被訂閱，撤回同意會阻擋下一次提交，測試回覆只進入本機接收端一次。正式 Discord 收聽、同意、自動回覆均仍關閉，沒有加入房間。證據為開發工作區 `.audit/discord-stt-real.mjs`／`.json` 與 `memu-stt-host-acceptance.json`。
