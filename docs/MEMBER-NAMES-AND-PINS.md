## 暱稱更新

Bot 與使用者帳號都支援。設定在「聊天快取 → 同步成員暱稱更新」，預設開啟。

- Bot 處理 GUILD_MEMBER_UPDATE，並利用語音狀態附帶成員資料補充稱呼。完整成員更新須同時在插件與 Discord Developer Portal 啟用 Server Members Intent。既有 Intent 設定不會自動更改。
- 使用者帳號透過 discord.py-self 2.1 的 on_member_update／on_user_update。事件受 Discord 下發與 SDK 快取範圍限制，不額外掃描全伺服器。
- 暱稱修改或清除會更新同伺服器聊天快取；全域名稱更新不會覆蓋其他伺服器的暱稱。身分、管理權限、允許名單與記憶來源仍依使用者 ID 判斷。
- 語音回覆沿用伺服器暱稱 → 全域顯示名稱 → 帳號名稱；缺少名稱時只查單一成員。使用者端只讀 SDK 快取，Bot 可唯讀取單一成員。查名最多等待 1.5 秒，不阻塞 TTS；舊查詢不覆蓋新事件，帳號／連線／房間／收聽政策變更後不提交舊語音。
- 名稱快取最多 1000 筆、查名並行最多 20。重新啟動後不保留名稱快取；原聊天快取仍依既有保存設定運作。
- GET /member-names 僅回傳啟用狀態、快取數與事件計數，不列出成員名單。

## 置頂

原本沒有專用置頂查詢；現在新增 discord_cyberfriend_read_pins。設定在「聊天快取 → 允許 AI 查詢目前頻道置頂」，預設關閉。

只允許正在處理訊息的正式 DSH 綁定會話。工具不接受帳號、操作者、頻道參數；依宿主目前 turn 固定來源，重核對帳號、操作者、inFlight、黑白名單、監控伺服器、設定與取消狀態。每次最多 20 則，只查該頻道、不分頁爬取全服、不下載附件、不觸發訊息回覆或長期記憶寫入；正文限長並遮蔽設定中的秘密。結果明示 dataOnly，不視為系統指令或新增授權。沒有讀取權限不假稱「沒有置頂」。

Bot 使用 GET /channels/:id/messages/pins 新版端點；使用者帳號沿用 SDK 的有界 pins iterator。需要檢視頻道與讀取訊息歷史權限。[Discord 官方說明](https://docs.discord.com/developers/resources/message#get-channel-pins)。未實作置頂／取消置頂寫入。

## 公告與引用

- 公告頻道的一般訊息原本即走正常接收／讀取流程；須具有頻道權限，並符合插件監控範圍。這不代表主動擷取全服公告，也不等於發布公告或跨頻道交叉發布。
- Bot 已補上與使用者端相同的有界最近對話與引用補讀，設定在「機器人 → 補讀最近對話與被引用訊息」，預設開啟；關閉聊天快取時不遠端讀取。
- 每頻道每帳號連線最近訊息補讀節流 60 秒、最多 20 則；被引用訊息僅讀同頻道且核對訊息 ID。舊查詢不在刪除、設定停用或帳號切換後重新寫入。補讀資料不重新派送為事件；套用已收到的最新名稱事件，避免 REST 歷史資料覆蓋新暱稱。
