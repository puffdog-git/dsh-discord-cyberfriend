# 錄製語音訊息與語音回覆

這與語音房收聽分開：不用加入房間，不會開啟麥克風持續收聽。設定頁「語音」可開啟「辨識錄製的語音訊息並以語音回覆」，並指定允許頻道、允許使用者與錄音時長。空白名單不處理；錄音作者也須列入名單。預設關閉。

需先在 DSH 準備 STT（例如本機 sensevoice-local），並在外部 TTS 插件選擇可用聲音。沿用 Discord 的 STT Provider／語言、每日 STT 秒數及 TTS 字數上限；不另建專用 TTS 網路接口。

## 觸發方式

- 同則音訊附件加上 @ AI。
- 回覆 AI 的上一則訊息並錄音。
- 引用自己的錄音訊息，再發 @ AI。
- 同使用者、同頻道、同帳號介面，在90秒內先錄音再單獨 @，或先單獨 @ 再錄音。多段只配對最近一段；過期不配對。不主動辨識舊歷史錄音，重啟後需重新傳送或明確引用。
- 允許頻道的一對一私訊可直接傳錄音。

Discord 原生語音訊息不允許同則附文字，因此第三、四種方式方便在分開送出的錄音與 @ 間建立關聯。這是確定的路由規則，不交給語言模型猜錄音對誰說。未被指向的錄音只作短暫配對記號，不自動辨識。

## 處理及輸出

只下載 Discord CDN 附件，最大8MiB，逾時45秒；同時最多兩個辨識工作。FFmpeg 真正解碼為16kHz單聲道PCM，依實際時長驗證，不只信附件宣告，也不截取前半段假稱完整辨識。原始音訊不額外落地。STT文字以使用者對話資料加入模型提示，不能授予額外工具或管理權限。

回答經外部 TTS 合成，輸出單聲道48kHz Ogg Opus、實際時長與RMS取樣波形，以8192旗標送成原生語音訊息。Bot 使用原本 REST/multipart；使用者帳號使用 discord.py-self 原生 handle_message_parameters／HTTP session 與限流處理。合成的暫存檔在發送結束即清理。失敗不偷偷重合成或改送純文字冒充成功。

語音訊息回覆目前使用原文配音；語音房的日文翻譯、背景音樂與插話開關不套用。使用者帳號若處於人工審稿模式，仍先產生文字草稿，並不繞過審稿直接送音訊。辨識後預設套用臺灣繁中與可選專名校正，見 [逐字稿處理](TRANSCRIPT-NORMALIZATION.md)；同音誤字仍可能保留。

普通文字回覆保留原流程。語音訊息流程不另發GIF、貼圖或模型情境表情，也不觸發語音房朗讀；原隨機表情仍受共用回覆檢查及開關控制。

正式契約：[Discord Voice Messages 與 Attachment Request](https://github.com/discord/discord-api-docs/blob/main/developers/resources/message.mdx)。離線驗證含真FFmpeg／Ogg、波形與時長、真正responder提示與交付、SDK multipart metadata、配對順序與隔離；實機結果另見開發工作區驗收報告。


## 中日配音與指定服務（2026-11-13）
錄音訊息回覆可使用日文配音，並另送中文文字；既有日文不重翻，翻譯失敗可只回中文文字，取消不發送。TTS 服務可指定本插件或宿主服務，指定失敗不換別套。仍須選擇支援日文的音色。
