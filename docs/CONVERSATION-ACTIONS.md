# 未答話題與自然語言延後回覆

私訊或明確 @ AI 後，可用以下操作。這些固定控制語句由插件直接解析，不需要付費模型判斷。

- 「半小時後再回覆我」或「明天下午三點半再回答我」：先預覽原問題與 Asia/Taipei 時間，再輸入回執提供的「確認安排 XXXXXXXX」。只有確認成功才交給 DSH 排程。
- 「晚點再回答」：先詢問時間，不自行猜測。「好」不視為確認。
- 「查看未答話題」：列出自己在原帳號、原頻道的未答來源及代碼。
- 「取消剛才的安排」「這題不用回了」或「結束話題 XXXXXXXX」：結束原來源，取消生成、未送出的草稿與關聯延後工作。
- 「繼續話題 XXXXXXXX」：預覽並確認後，重新讀取原問題，走正常權限、模型、冷卻與預算流程。

多個話題時，請引用原問題或帶話題代碼；不會猜測要操作哪一題。群聊操作須明確 @ AI（有效確認碼可在同一對話直接回覆）。引用文字、假設句、別人的提及不當成指令。現階段採固定句型，複雜自由敘述仍可能需要改寫。

## 介面與排程

設定分區新增「話題與延後回覆」，可搜尋、顯示已結束項目、預覽延後、預覽重新回答與確認結束。重新整理後如話題已變更，舊操作會被拒絕，需重新預覽。

需先有原對話的正式 DSH 會話綁定及可用的宿主 schedule 服務。插件不另建計時器；到期仍由 DSH 喚醒，無法保證忙碌宿主準時完成。時間範圍一分鐘至七天；明確時鐘需區分上午／下午，日期以 Asia/Taipei 計算。確認碼五分鐘、一次有效，確認時剩餘不足一分鐘需重設。排程保留原定時間，最小秒數取整誤差不足一秒。

到期會重新核對帳號、頻道、作者、權限、來源內容及附件、DSH 會話綁定與話題版本。連發合併問題會重新讀取最多八筆來源。改字、來源消失、更正或忘記政策、改綁會話、帳號更換與話題結束均阻止舊安排送出，不自動改投其他帳號或收件人。新提出的問題不會自動併入既有延後工作。

此功能延後既有文字問題，不是通用提醒建立器，也不替他人授予主動關心同意。即時語音的合成來源 ID 無法從 Discord 重讀，不能用來延後／重新回答；請改用文字來源。

## 取消與紀錄範圍

取消不刪除 Discord 訊息、長期記憶或已送出的內容。已開始送出或結果不明時會提示核對，不承諾追回。宿主排程刪除失敗時，本地仍阻止交付並明示未確認，不再自動重試建立或回覆。重啟時執行中的狀態轉為結果待核對，不自行重跑。

話題檔只保存來源 ID、所屬身分、交付目標、版本與狀態，不另存問題正文。預覽讀取既有聊天快取，沿用敏感資訊遮蔽。預設保留十四天（可設一至三十天）、最多二百筆；仍被有效排程引用的來源不因天數被清除。確認預覽最多一百筆、只存記憶體，重啟失效。控制回執另限每個範圍每分鐘八次，不消耗模型回覆的額度；重新回答仍受原額度限制。

## 模擬驗證

單元測試使用真 ConversationDesk 與 CompanionControls 搭配替身 Discord、模型及宿主排程；另透過實際 index、守門員、Responder 與管理 API 驗證完整入口。瀏覽器驗證預覽／返回／確認／關閉、錯誤恢復、繁簡搜尋及手機寬度。沒有建立真實排程、付費模型呼叫或測試 Discord 外送；不代表真實宿主喚醒時效或遠端收聽品質已驗收。
