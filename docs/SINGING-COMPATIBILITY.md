# 外部唱歌插件兼容性評估

後續更新：已完成獨立工作橋接與模擬交付，見 [SONG-WORKFLOW.md](SONG-WORKFLOW.md)。以下保留原始評估；其中尚未安裝／尚未串接的描述應以後續文件為準。真實 MSST／DDSP 聲庫仍未配置，未驗收實際翻唱品質。

2026-11-13，僅檢查公開原始碼、工具契約及隔離測試，不下載歌聲模型或產生商業歌曲。

## 結論與分工

兩套都能作為獨立 DSH 工具來源，輸出本機 WAV，適合由 Discord 接收成品。保持以下分工：Discord 接收請求及交付音訊，DSH 協調工作，外部唱歌插件管理引擎與模型。TTS 繼續處理說話合成，不內嵌唱歌／分離／換聲引擎。

| 插件 | 輸入與用途 | 輸出／需求 |
|---|---|---|
| dsh-neutrino 0.1.0 | 歌詞逐音對齊的旋律譜，主打日文歌聲合成 | WAV；另需 NEUTRINO 引擎與聲庫；無引擎仍可寫 MusicXML |
| dsh-cover-pipeline 1.1.3 | 原曲錄音分離人聲／伴奏，再換聲、移調與混音 | WAV／驗收結果；另需 MSST、DDSP、模型權重與 Python 環境 |

依兩者輸入設計，中文既有歌曲如《雨愛》較適合先評估 cover-pipeline：用有權使用的原曲檔，保留原演唱的旋律與節奏，再換音色。NEUTRINO 較適合已有日文歌詞及旋律譜的演唱；此插件預設聲庫不能直接視為中文演唱引擎。

## 現有 Discord 的實際缺口

1. 已有 `discord_send_file` 可以送本機成品附件，但仍受會話工具政策約束。
2. 語音房已具備 Bot／個人帳號播放、音樂佇列及音樂音量策略；現有 `voice.music()` 經音樂插件 `/music/stream` 或線上曲目路由讀取，不是直接接收任意外部成品檔。尚無 Agent 的「播放本次唱歌工作成品」工具。
3. `allowedReplyTools` 目前只在管理者的一對一私訊允許明確列入白名單的工具，一般頻道仍不授予 Agent 工具。僅安裝外部插件，不會自動讓伺服器訊息啟動 GPU 唱歌。後續應設計專用唱歌命令及角色／頻道範圍，不放寬成全部通用工具。
4. 唱歌可能耗時數分鐘，需獨立工作狀態、取消、排隊及成品有效性檢查。NEUTRINO 的 subprocess 未接入 exec.signal／逾時，且同曲名可共用引擎 score/output 路徑；應使用單工作排程及唯一名稱。cover-pipeline 有階段逾時及輸出鎖，但也未直接接 Discord 取消訊號。
5. 交付必須使用本工作明確回傳的成品路徑，不能抓全域「最新輸出」，以免跨會話送錯歌曲。NEUTRINO 主要回傳文字中的 WAV 路徑；cover-pipeline 回傳結構化階段 artifacts，皆須確認存在及成功狀態，dry-run 不算音訊。
6. 一般 TTS 音色 ID 與唱歌聲庫／DDSP 模型不同，需另有「人格 → 唱歌聲庫」設定，不能假設同一個音色 ID 可共用。

完整歌曲應用成品附件或語音房音樂播放；目前原生短語音橋接限制 60／120 秒，不能直接拿來交付數分鐘歌曲。Discord 音樂路徑已有自己的分鐘上限設定，但外部成品直入接口仍待補。

## 音源如何取得

- 原曲錄音：使用者上傳／指定可使用的本機 WAV、FLAC、MP3，或自己錄唱。cover-pipeline 可從完整原曲分離人聲與伴奏。
- 已有分軌：提供可使用的主唱人聲及伴奏，省去部分分離工作。只有純伴奏時，換聲仍缺少「要換成誰的」原演唱人聲，需先錄唱或用歌聲合成產生主唱。
- 旋律譜：使用者提供 MIDI／MusicXML／明確音高時值與歌詞對齊，供歌聲合成引擎使用。NEUTRINO 目前工具直接接受音符 token／MusicXML，不應假稱已具備任意 MIDI 自動匯入或從歌名準確還原整首旋律。
- 只提供歌名時，仍需要音源或樂譜。這兩個插件都不是歌名搜尋及音樂下載服務，且插件不附帶歌曲錄音。

目前 TTS 的文字／語氣提示流程沒有樂譜、音符時值及整首配器控制，不能保證靠「唱歌語氣」重現指定歌曲。適合把外部唱歌成品當作音訊檔交付。
