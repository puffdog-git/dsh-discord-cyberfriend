# 第四步：Discord 情境語氣

Discord 在同一次回覆模型呼叫中，依既有聊天上下文產生限值的 emotion／intensity／pace；不是逐句再呼叫分類模型。內部 speech_meta 會在任何文字／Embed／GIF 組裝及審稿之前移除，不送成對外聊天正文。模型缺少、格式錯誤或重複的資料回到自然聲。

優先序為本次明確語氣 → Discord 手動語氣 → 固定／本次模型情境 → TTS 預設。個人帳號審稿只保存資料；收到真正送出確認後才排語音。使用者編輯正文時捨棄舊的模型語氣，避免「改成開心的文字卻仍用悲傷語氣」。取消、預算、分段與快取沿用原工作，不為每段重做情境判斷。

適配層位於 Discord。支援自然指令的服務收到獨立 instruction；MiniMax／Cartesia／Azure 收到實際固定情緒／SSML 風格；Index 收到已核對順序的八維向量。Index 的興奮以開心＋驚訝近似，MiniMax 以 happy 近似，均回報差異。Cartesia 僅依英文情感契約啟用；不支援語氣的引擎保留聲音並回報降級，絕不把情緒文字硬加進朗讀正文。已有 Index 獨立情緒錄音時保留該錄音，不混入衝突的向量。

7 組新增測試涵蓋上下文／同文不同語氣、手動覆寫、無效輸出、各家參數、長文沿用同一決策、通用宿主服務、審稿與編輯。Discord 全部 161 組通過。真實 Index2.5 對同一句中文，興奮組合輸出約3.67秒、悲傷輸出約5.50秒，音訊不同；保存了可試聽 WAV。這證明參數通過真實推理並改變聲音，不等於已完成人工情緒品質或聲紋評分。沒有真實 Discord 外送或付費雲端測試。

本階段仍維持外部 TTS 不包含 Discord 接口。後續正在依使用者整批交辦加入中日語音、人格／工作區／會話音色，以及 DSH 中立音訊交付。
