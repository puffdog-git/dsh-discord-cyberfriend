# Discord／TTS 生態系現況與缺口

2026-11-13，核對正式來源、歷次報告與隔離測試。目標是虛擬朋友／伴侶／家人／群友；Discord 專注訊息理解、對話路由與交付，人格、情緒及長期記憶交由專門插件。

## 已確認的具體問題

優先級表示建議處理次序，非 CVSS 分數。下列問題本輪僅審核及隔離重現，尚未修復。

| 優先 | 問題與證據 | 建議修復 |
|---|---|---|
| P0 | Discord 管理 HTTP handler 未做來源／身分驗證。真宿主 schema-only 無憑證與 cross-site 均 200；隔離 POST /config 以 text/plain 及跨站來源能呼叫 setConfig 並回 200。當前 webServer 路由直接呼叫 handler，不能假設宿主 RPC 的認證會保護這條 prefix | 在統一入口使用真正宿主身分驗證、來源／Host／Fetch Metadata／CSRF 及 JSON content-type 檢查；管理讀取也要驗證，不只寫入。覆蓋設定、登入、手動送訊息、審稿、模型測試及語音等入口 |
| P1 | Discord saveConfig 將 activeConfig 原樣寫入 data/config.json，包括設定中的 secret 欄位；UI 遮罩不等於磁碟加密 | 改用宿主安全憑證庫／Windows DPAPI 或對應平台金鑰圈，原子遷移及失敗回復，不讀出或列印憑證；發布／備份繼續排除 data |
| P1 | 日誌 scrub 只按欄位名稱遮蔽；測試假金鑰放在 error 字串仍保留 | 在錯誤、摘要、巢狀字串及可下載診斷共用值遮蔽；測試 API 回應與子程序 stderr。此測試不表示已發生真實外洩 |
| P1 | 翻唱 sourceUrl 僅做部分字串黑名單，0.0.0.0、100.64.0.1 仍通過；未驗 DNS／重導向每跳 | 與下載器協商真正 public-only 出站策略、DNS／重導向檢查及重新連線限制。不能只在工作起點驗一次 URL；TTS Registry 的 public-download 已有較強實作可參考 |
| P1 | VoiceMessages.sendReply 寫死 spokenLanguage:original，未轉交日文 spokenText；設定 ja 的隔離呼叫仍送 original | 錄音回覆共用既有最終正文→翻譯／用語表→音色快照流程，保留取消與預算，不另做重複翻譯 |
| P1 | auto／service 都優先 dshTts，再找 speechSynthesis；兩者同裝的隔離測試不能指定小米 | 增加明確服務選擇、來源與能力快照；切換不重送已開始的合成，不改 TTS 引擎自身設定 |

HTTP 證據只做本機唯讀請求；設定寫入只發生在假 handler／假 config，未改正式設定、未外送。這證明缺少檢查，不等於已證實外網暴露或所有瀏覽器可成功 CSRF；瀏覽器私人網路限制、監聽介面及反向代理仍會影響可達性。不要把 CORS 當成寫入授權。修復方向依 [OWASP REST 安全](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)；出站 URL 依 [OWASP SSRF 指引](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

## 訊息核心最值得補什麼

1. **等對方說完與追補**：同一人「我明天要出門」「不是早上，是下午」「幫我記一下」應合成同一回合。生成中到來的補充可使待送答案失效並重新規劃；不能把三句各扣一次冷卻後漏兩句。不同人、不同群、不同權限絕不直接合併。
2. **多人對話的收件人與待答問題**：目前 followup 每頻道只有一位最近對象，成功回覆後才建立窗口。應追蹤有限的參與者／話題／引用／未答問題與暫定回合，使「A 問一題、B 插話、A 接著說」仍回對人。這是短期路由狀態，不另建關係人格庫。
3. **同人格多帳號單一回覆者**：Bot／使用者帳號去重 key 含 transport.kind，沒有通用跨帳號 claim。加入原訊息＋人格＋頻道的擁有權，確定由哪個介面回答，避免雙答與互相接話；不同人格可明確允許各自回應。
4. **將沒回覆的原因說清楚**：現有收件匣以使用者帳號較完整，擴成 Bot／語音／跨插件共用 trace，清楚顯示等補充、冷卻、預算、審稿、取消、未交付及結果不明。只留必要中繼資料，不再複製一份私人正文。
5. **更正、忘記與刪除的可驗證處理**：刪 Discord 訊息目前移除即時歷史，但日記事件保留來源並標 deleted；不代表 DSH 正式會話、已匯出檔與外部記憶同步刪除。應提供刪除範圍預覽與各層回執，不支援撤回的插件如實說明，memU 繼續預設。

## 有陪伴感、但不侵入人格插件的創意

| 功能 | Discord 應負責 | 委派外部插件 |
|---|---|---|
| 「等我一下／這個晚點回」 | 延後回覆狀態、期限、取消、恢復時重新核對上下文 | DSH 排程，不自建另一套時鐘服務 |
| 未完話題與承諾追蹤 | 記錄哪則訊息尚待回覆或已承諾回覆；可一鍵結束 | 長期事實交記憶插件；關係意義交人格插件 |
| 安靜陪伴／只聽／文字優先／夜間不出聲 | 依頻道、使用者及時段決定訊息和語音出口，避免「安靜模式」仍播放聲音 | 音色及情緒交 TTS／人格方案 |
| 經同意的主動關心 | 管理者選擇範圍、安靜時段、每日上限、未回不追問、立即停止 | 內容依人格／記憶提供；不預設向陌生人私訊 |
| 「剛才沒聽清楚」 | 依明確原訊息重播已核對音檔，保留作用域與費用資訊 | 優先重用成品，避免重新付費合成；超出保留期才明示重做 |
| 一次分享多張圖／錄音＋補充文字 | 合併成一個訊息包，標明資料來源及不確定性，避免只理解最後一張 | 視覺／STT／文件解析交外部能力 |

上述均是候選，尚未實作。沒有必要自己做另一套好感度、情緒日記、靈魂設定或戀愛狀態機。

## 第三方生態的界線

- **TTS**：我方修改版有真人播放；原版 GooDAnDReaDY 0.4.42 核對 HTTP 接口及既有模擬；memef1f1y 有接口模擬；小米 5.3.0 有真服務＋模擬上游＋真轉碼。Yuuyuko 朗讀橋只做瀏覽器播放，無可回傳音訊，不能直接兼容。不要把這些等同每套 Provider 的真實帳戶驗收。
- **通訊**：OneBot／QQBot／IM 已有獨立 speech bridge；多平台原生泡泡依本機 IM fork，原版不自動獲得該能力，升級可能覆蓋。需要版本／能力協商及安裝狀態矩陣，避免只顯示「已安裝」。
- **記憶**：九類兼容不代表每家均有專用寫入器；有些是正式會話捕獲，有些為檔案候選。更正／刪除／召回能力須逐家宣告，不能把寫入 ID 當刪除契約。群內共工作區是既有設計，頻道與人格要共享還是分庫應讓使用者看得見；跨平台身份不能按暱稱自動合併。
- **人格**：已有大肥魚適配器與公開 registerPersonaAdapter；其他熱門人格插件尚未逐套驗收。可提供最小 persona ID／名稱／生效狀態契約及套件作者範例，不把完整私人人格提示拷給所有插件。
- **Skill**：五項已歸 Discord，負責多步調度，不保證所有下游工具獲得授權；目前 sessionAllowedTools 空清單是原安全限制，不應為了群聊唱歌而全開。將來需設計按操作者／頻道限定的媒體工具能力，保持一般群友不能讀檔或改設定。

## API 安全已有什麼、還欠什麼

已有管理者不可由暱稱冒充、一般群友工具清單受限、輸出敏感資料遮蔽、附件來源白名單、大小／時長／取消、工作區成品隔離、TTS 管理入口來源檢查、Registry 雜湊與 DNS 檢查、自管程序生命週期。這些應保留。

仍需檢查所有 HTTP 路由，而非只主插件：speech bridge、IM fork、本機模型服務及重啟服務各有自己的信任邊界。TTS helper 對非轉送 loopback 在驗宿主 connection 之前放行，屬較寬的本機信任策略，應明確界定本機管理能力及反代標頭，不把它宣稱零信任。對同程序已載入的第三方插件也沒有沙箱保證；禁止普通聊天工具不能防止惡意已安裝插件。

還應補共用追蹤 ID、入口頻率與資源上限、憑證槽對目的地主機的可見綁定、診斷輸出內容遮蔽，以及相容性契約回歸。完整依賴 CVE 掃描、真瀏覽器攻擊鏈、外網部署和每個 Provider 帳戶權限不在本次驗證範圍。

使用者帳號自動化另外存在平台限制：Discord 官方禁止 self-bot，不能承諾任何 typing／限速設計可避免偵測或封號。穩定的公開發布應以 Bot 為主要支援路徑。[Discord 官方說明](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots)
