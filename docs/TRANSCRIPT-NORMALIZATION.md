# 逐字稿繁中與專名校正

語音房接收與錄製語音訊息共用這三個設定，套用於辨識後、字幕／模型輸入之前。使用固定版本 opencc-js 1.4.2 的本機字典，不另呼叫模型，也不下載轉換字典。

- **逐字稿繁中轉換**：預設「臺灣繁體與常用詞」。可選僅臺灣繁體字形，或保留辨識原文。指定 zh／yue 才轉換；auto 遇到日文假名時略過，明確指定 en／ja／ko 等非中文亦不轉換。中文日文混寫或只有漢字的日文仍可能無法單靠文字判斷，這時選保留原文或指定 STT 語言。
- **逐字稿專名校正**：預設啟用，內建 Deep Seek → DeepSeek、Eleven Labs → ElevenLabs、Open AI → OpenAI、Chat GPT → ChatGPT、Fish audio → Fish Audio。以完整英文字邊界比對，不會把 Deep Seekers 改成品牌名。
- **逐字稿專名對照表**：預設 `{}`。例如 `{"大肥余":"大肥魚","迪艾斯艾趣":"DSH"}`，只填你確認會誤辨的詞。這些是使用方式示例，不是預先替你啟用的個人詞彙。最多100組，原詞最多80字、正確名稱最多160字。自訂詞逐字比對，較長詞優先，同位置只替換一次，不連鎖改寫；簡體原詞在繁中轉換後仍能命中。錯誤 JSON／資料型別／過長值會在儲存時拒絕。

網址、Email、Discord提及與程式碼區塊不轉換、不套字典。結果仍經敏感資訊遮蔽與長度限制；不額外保留一份原始逐字稿。回傳 normalization 只描述模式、是否轉換與替換次數，並非模型辨識信心。

這不是同音辨識模型：沒有詞表時，「辨試」不會自行猜成「辨識」，也不會推測人名、地名或憑空補出漏字。模型的文字回覆與 TTS 發音字典各自獨立，本功能只處理 STT 辨識文字。

驗證包含字形／用詞、英文品牌邊界、較長詞優先、非連鎖替換、Unicode Email、日文略過、錯誤設定與兩條入口交付。另以免費 Edge 測試音訊 → 真正 DSH SenseVoice → 實際 VoiceMessages 流程，確認簡體逐字稿轉為繁中並套用隔離測試詞表；沒有向 Discord 發訊息或加入語音房。

依據：[opencc-js 官方使用方式](https://github.com/nk2028/opencc-js)。
