先區分語音房即時收音、頻道錄音訊息、TTS 試聽或一般音訊附件。確認實際帳號／頻道／會話與使用者允許的收聽、回覆範圍，沿用原 STT、TTS 服務與預算。

## 依首個失敗點檢查

- 接收：語音房須已加入、允許使用者且接收開啟；錄音訊息由獨立的 voiceMessage 設定管理。檢查錄音是否確實指向 AI（回覆／提及／允許的錄音與提及配對），不能因看見附件就辨識所有人的錄音。
- STT：查看宿主 speechToText 的可用性、選定 Provider、模型準備狀態、格式與時長。`sensevoice-local` 是本機選項；若使用者選 `external:dsh-voice`，需獨立 dsh-voice、speech bridge 與宿主辨識服務均已啟用。
- dsh-voice：在原插件配置「聽寫辨識鏈」及語言；橋接取 rawText／verbatim，不做潤飾或執行語音巨集。它可能使用雲端及自己的降級鏈，不能宣稱本機隱私；不支援逐次覆寫語言。不可用時不要默默切回其他 STT。
- AI：確認逐字稿已送入正確正式會話、回覆開關與模型可用、預算未耗盡。繁中與專名校正只修字形／指定詞，不能保證修復同音誤辨。
- TTS：檢查實際服務鏈、音色解析、語言及合成錯誤。401 要看服務錯誤內容；ElevenLabs 的模型／聲音清單涉及 models_read／voices_read，合成另需服務所要求的 TTS 權限，不把所有 401 都當免費額度不足。金鑰在原服務設定，不輸出到報告。
- 交付：區分未排程、合成失敗、等待審稿、佇列取消、已發送及結果不明。有文字無聲音先檢查語音輸出與取消原因；截斷再查插話中斷、時長上限、解碼完整性及播放完成狀態，勿直接把所有問題歸因於 Provider。

管理者可從 Discord 的語音頁及唯讀 `GET /api/discord-cyberfriend/voice`、`GET /api/discord-cyberfriend/voice/overview` 檢查狀態。`GET /voice/check` 會刷新服務診斷；不把管理 HTTP 介面當普通模型工具，缺少管理權時使用可見 UI 或已授權工具。

## 測試及修復

使用者指定模擬時，只用隔離音訊／替身及現有測試，不加入房間、不播放、不送 Discord 訊息、不啟動付費服務。真實測試必須沿用已授權房間與使用者；不要為測試擴大到整個伺服器。更換雲端服務、下載模型或啟用收音需符合當前任務授權。

取消後下游不提交回覆，但外部 dsh-voice 已開始的 HTTP 辨識可能等到自身逾時才停止。播放結果不明不盲重送。回報通過哪一段、首個失敗點、修改與剩餘驗收界線；即時收音、Opus、佇列及中斷仍由程式處理。
