先辨識目標是人格共用、某工作區或單一會話，從實際 Discord 綁定取得 session／workspace，不能猜目前瀏覽器頁面就是目標。使用 TTS 的「人格與語言」設定與 Discord 音色總覽核對實際解析結果，不只看全域預設。

## 音色方案

- 在 TTS「語音來源」選 Provider／模型／聲音，再將設定存為具名方案並綁定目標。方案與綁定立即儲存，全域來源設定另需儲存；方案只存憑證槽名稱，不複製 API Key。
- 解析優先序：單次明確方案／聲音 → 會話 → 工作區 → 人格 → 全域。若人格綁定沒有生效，先檢查較高層覆寫，再修改需要的層級。
- 多個人格適配器同時回報生效人格時，不猜測；明確選擇 personaAdapter 或採工作區／會話綁定。未安裝人格套件仍可綁定工作區／會話，不讀取完整私人人格提示作為診斷輸出。
- 有公開 `dshTts.resolveVoice({sessionId,workspaceId})` 介面時可唯讀核對。TTS profiles 管理 API 修改要帶最新 revision，衝突時重讀，不直接覆寫 voice-profiles.json。刪除方案不等於刪除雲端聲庫或模型。

## 中文文字與日文聲音

保持公開中文回覆，選擇支援日文的模型／音色。Discord 使用 `voiceSpokenLanguage=ja`；TTS 的方案配音語言為 `spokenLanguage`。不要只改聲音標籤，卻讓模型朗讀中文假裝日文。

Discord 優先在同次回覆生成中文與隱藏日文 spokenText；缺少有效日文，或公開正文經審稿／裁切後，才對最後正文補翻一次。依目標設定日文用語表及補翻選項，沿用 Token 預算。不再另建每句情境分類呼叫；emotion／intensity／pace 已由原回覆流程處理。

若上游已提供有效日文配音，避免在 TTS 再翻譯一次。只有通用 TTS 路徑負責翻譯時，才在該層選 ja。格式／假名驗證不等於翻譯及發音品質驗收；翻譯失敗保留中文文字，不能默默把中文當日文播放。沒有支援日文的引擎就明確回報，不假稱所有本機模型都是多語。

## 驗收

先唯讀核對選定方案、來源層級與語言，檢查是否影響其他角色。使用者要求試聽時，以不含私人對話的短句確認；已授權真人播放才能向 Discord 發送，模擬要求則保持隔離。修改不會改動已開始的合成快照。

回報哪個人格／工作區／會話綁定哪個方案、實際 Provider／聲音、覆寫來源、配音語言與是否仍待聽感驗收。不要為修正一個角色而重設全域或其他綁定。
